## Q1 一句话背景

`"ab".length` 已落地（`548fbbe`）。它是这条路上**唯一不需要绑接收者**的一格——
`length` 是值不是方法。其余全部卡在同一个问题上，三条候选：

- **A · `this`** —— 跟规范走。**带一笔债**：`this` 一落地，
  `plan/design-arrow-milestone.md` §1「箭头就是函数表达式」的等价立刻作废。
- **B · 绑定闭包** —— 属性读返回一个环境里装着接收者的函数值，复用闭包机制。
- **C · 调用点特化** —— `a.map(f)` 直接编成 `__arr_map(a, f)`，不产生函数值。

主判据是**斜率**（加第五个方法的边际字节 / 行数），不是截距。
主产出可能是判据 ⑥ 那张**泄漏清单**。

## 判决（2026-08-28）

**变体 C（调用点特化）胜。** 三个变体全部实现、判据 ① 各 **7/7**、语料未改一字。

判决 trace：③ 三方打平（0，真的加了第五个方法 `pop` 重测）→ ③b/③c 各赢一条、
互不支配 → ④ 打平（每方法各 1 行）→ **⑥ 泄漏清单最短者胜：C 六条，B 八条**。
截距（⑤）同样指向 C。**变体 A 被 B 严格支配**，先行出局。

C 赢在**不向不相干的代码收费**：加四个与方法无关的函数，C **+0**，B +120，A +136。
以 `fleet.qjs`（29 个函数）为参照，B 光这一项就要付约 870 字节。

**适用范围**：若出现「函数极少、方法调用极多」的载荷（约 40 个以上调用点），
这条判决应当重开。

**最值钱的一条**：C 的 `map` 一度读成每调用点 162 字节（B 的 5.4 倍），
眼看要判 C 负——它内联整个循环，只因为当时以为「没有 prefab 能 `call_indirect`」。
**B 证明了能。** 给 C 也换成 prefab 后 **162 → 48**，判决从 B 翻到 C。
所以可修性检查不只对自己那个变体做：**任何变体推翻一条共同前提时，所有变体都要重测。**

数字与完整 trace 见 [`RESULTS.md`](RESULTS.md)。

## 分档（2026-08-28 补测）

原记「L1/L2 未测定」。补测后有两件事要说：

1. **skill §2.5.1 的三档对这个设计不成立。** 那个模板假设机制是**一组函数**；
   赢家的机制是发射在**每个调用点**上的代码，不是函数。所以 **L1 就是「每调用点」
   那个数**，没有第二个数可报——照模板硬报一个只会是编造。
2. **L2（每个方法体，含私有 helper）已测**：`trim` 518、`indexOf` 337、
   `push` 73、`pop` 108、`map` 151 字节。

还有一条**容易混的**：这里的「每调用点」（75–164）与判据 ③b（43–53）**不是同一个数**
——基线不同，问题不同，两个都对。详见 [`RESULTS.md`](RESULTS.md) 那张对照表。
判决用的是 ③b，不受影响。

## 判决之后 —— **已执行**

规格 §5 要求的收尾做完了：

- `method-bound`、`method-this` 两个 feature 及其全部代码路径**已删除**；
- `method-callsite` 的实现**已转正**为无 feature 的常规实现（`src/method.rs`）；
- `method_conformance.rs` 去掉了 `#![cfg(...)]`，成为常规测试——它写在任何实现
  之前，三个变体都原样通过，所以它现在是这批方法的行为规格；
- `measure.rs` 与三个 feature 一起退休，它记录的数字留在 [`RESULTS.md`](RESULTS.md)。

**转正前补掉了一个已记录的缺口**：`ws_width` 原本只认具名的十个空白字符，
不认 `Zs` 其余（U+1680、U+2000..200A、U+202F、U+205F、U+3000）。
研究期这个缺口三个变体同价、不影响比较；**上线则是错答案**——
`"\u{2003}a".trim()` 会留着那个空格而且没有任何诊断说这件事。已补全，
并连同两个「看起来像空白但不是」的字符（U+200B、U+2060，属 `Cf` 不属 `Zs`）
一起钉进语料。
