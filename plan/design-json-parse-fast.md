# `JSON.parse`：整数一趟读完，字符串四字节一步

| | |
|---|---|
| 日期 | 2026-08-29 |
| 状态 | 已落地：`convert.rs` `json_pnum` / `json_pstr` / `jb_bytes` / `jb_take`，`tests/json_parse_cost.rs` |
| 起因 | 下游按内容二分实测：短整数 ≈270 步/字节（每个五位数 ≈1 600 步）、字符串 84–119 步/字节、小对象 ≈200 步/字节；393 KiB 的目录 100M 步都读不完（wave-2 script-smoke 第一步就停） |

## 两条快路径

1. **整数**：`json_pnum` 原来先验语法、再把接受的文本**拷进新记录**、再交给 `__str_to_num`
   **重新解析一遍**。现在验位数时顺手累加 `val = val*10 + d`（≤15 位精确，与
   `__digits_to_f64` 的 Clinger 精确情形同一条理由），无小数、无指数即直接返回。
   **1 600 → 527 步**（剩下的是每位一次 `__jp_at` 调用）。
2. **字符串**：`json_pstr` 原来每个字符一次 `__jb_byte` 调用。现在遇到可打印 ASCII
   （非 `"`、非 `\`）就扫一段整段追加：**四字节一步**——一个字里「有字节 < 0x20 / 高位置 1 /
   等于 `"` / 等于 `\`」用经典的 `(x - 0x01010101) & ~x & 0x80808080` 判；指令集没有 xor 与 not，
   `a^b = (a|b)-(a&b)`、`~x = -1-x`。`__jb_bytes` 与 `__jb_take` 的拷贝同样四字节一步。
   1 000 字符的串：**119 → 29 步/字节**。

## 代价

只有点名 `JSON` 的程序付：JSON 集 +329 B（run 分支 + `__jb_bytes`）再 +（本次字宽）；
`"return 1;"` 不动。数字见 `arrays_m3.rs` 历史块。

## 没做的

小数也走快路径了（同夜第二步：分数位一起累加，除以一次精确的 10^fd；`1.5`：1 336 → 539）；指数仍走 `__str_to_num`；每位一次 `__jp_at` 可以内联；对象键
（短串）仍付每串一次 buffer new/take/push（十字符串 ≈70 步/字节的主因）。
