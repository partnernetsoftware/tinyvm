# `.length` 按字数

| | |
|---|---|
| 日期 | 2026-08-30 |
| 目的 | `__len` 逐字节数 UTF-16 单元：6 000 字符一次 180 346 步（30 步/字节），且每次 `.length` 都重数——`for (i < s.length)` 是 O(n²) |
| 位置 | `crates/tinyvm-qjs/src/runtime.rs` `length`；钉在 `tests/length_cost.rs` |
| 由头 | agenterm 两条端到端旅程各要 33M–45M 步，拆开是 `append_command_record` 每次 ≈970k，其中 `bounded_record_text` 的一次 `.length` ≈300k |

## 做了什么

字节循环外面套一层字循环：还剩八字节且两个 i32 load 或起来 `& 0x80808080 == 0`（指令集没有 i64 `and`），
就 `n += 8; i += 8`。第一个不纯 ASCII 的字交回字节循环处理一个字节，字节循环每走一步又回到字循环，
所以多字节字符之后的 ASCII 继续按字数。

## 数字

| | 前 | 后 |
|---|---|---|
| 6 000 字符 `.length` 一次 | 180 346 | **19 854** |
| 能到串 `.length` 臂的程序字节 | 10 249 | 10 307（+58） |

`tests/json_parse_cost.rs` 的「五位整数」从 527 读成 ~700：它的基线程序里有一次串 `.length`，
原来贵 18 000 步把差值压小了；解析本身没变，注释里写明，阈值 700 → 800。

## 没做的

- 把单元数存进串头（O(1) `.length`）：改串的布局，所有 `I32Load(2,0)` 读长度的地方都要跟着变；
  按字数之后 3.3 步/字节，二次循环的常数已经小 9 倍，先看够不够。
- 十六字节一步：再省一半，等有程序证明需要。
