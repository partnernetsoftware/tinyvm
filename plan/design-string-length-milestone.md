# `"ab".length`：第一个非 Object 接收者上的属性

| | |
|---|---|
| 日期 | 2026-08-28 |
| 目的 | `"ab".length` 给出正确答案；**没写 `.length` 的程序反而更小** |
| 实现位置 | `crates/tinyvm-qjs/src/runtime.rs`（`obj_get` 一条臂、`length` 计数器）、`src/array.rs`（`prop_get` 归并）、`src/emit.rs`（门） |
| 前置阅读 | ECMA-262 6.1.4（String 是 UTF-16 码元序列）、22.1.3.2（`length`） |
| 验收 | `crates/tinyvm-qjs/tests/string_length_m3.rs`，9 项 |

## §1 这不是原型链，只是一条臂

`runtime::obj_get` 在 `unbox_object` 之前多了一条臂：接收者是 String 且键等于
`"length"` 时，调 `__len`；**其它任何键仍然 trap**。

「其它键返回 `undefined`」是这里明确**不做**的事，理由与数组正相反：

| | 越界索引 `a[9]` | 未知字符串属性 `"a".trim` |
|---|---|---|
| 真 JS 里是什么 | 确实不存在 | `String.prototype.trim`，**是个函数** |
| 返回 `undefined` | 是**对**答案 | 是**错**答案，且看起来像对的 |

所以数组选 `undefined`，字符串选 trap。这条区别写在 `obj_get` 的注释里，
也写在 `string_length_m3.rs` 的文件头——它是本里程碑唯一容易被后人改反的地方。

顺带把 `array::prop_get` 简化了：原来先测 `TAG_OBJECT` 走 `obj_get`，再单独测
「也不是 Array」去 trap。现在一条测试——**不是 Array 的全是 `obj_get` 的问题**——
`undefined[k]` / `null[k]` 仍由 `obj_get` 自己的接收者测试 trap，字符串的
`.length` 也就自动跟着走通了，不必在两处各写一遍。

## §2 数的是 UTF-16 码元，不是字节——这是本里程碑差点出的错

`__len` 原来的实现返回记录头里的**字节数**。ECMA-262 6.1.4 说 String 是 UTF-16
**码元**序列，22.1.3.2 说 `length` 是码元个数。两者在纯 ASCII 上一致，在别处不一致：

| 字符串 | UTF-8 字节 | UTF-16 码元 |
|---|---|---|
| `"café"` | 5 | **4** |
| `"中文"` | 6 | **2** |
| `"😀"` | 4 | **2**（代理对） |

第一次测的时候 `"café".length` 给的是 5。**这正是「错答案穿着对答案衣服」的形状**——
它在绝大多数字符串上都对。所以计数改成一个循环：

* 非续字节（`(b & 0xc0) != 0x80`）开启一个字符，至少一个码元；
* `b >= 0xf0` 是四字节序列，码点在 U+FFFF 之上，是**代理对**，再加一个。

字符串按构造就是合法 UTF-8（要么是编译器 intern 的字面量，要么是 `__str_concat`
用两个这样的拼出来的），所以不需要校验，只需要数。

四种宽度各有断言，并且有一条把四种混在一个字符串里——防止某一档的错误被另一档抵消。

## §3 门：**负**的代价

`__len` 在**无条件** runtime 集合里，索引固定，每个模块都发射——而在本改动之前
**没有任何调用点**。也就是说它一直是死重。

于是门做在**函数体**上而不是集合成员上（动集合成员会移动后面所有函数的索引）：
`ctx.string_length` 为 `None` 时，`length()` 只发一条 `unreachable`。

实测（基线取 `9e02e37`）：

| 程序 | 之前 | 之后 | Δ |
|---|---|---|---|
| `return 1;` | 9784 | 9765 | **−19** |
| 字符串拼接 | 9836 | 9817 | **−19** |
| 对象 | 9873 | 9854 | **−19** |
| 闭包 | 10051 | 10032 | **−19** |
| JSON | 15448 | 15420 | **−28** |
| `o["a"]`（键写死） | 9847 | 9828 | **−19** |
| `a[1]`（字面量下标） | 10619 | 10591 | **−28** |
| `a[i]`（变量下标） | 10612 | 10707 | **+95** |
| `"ab".length` | 9802 | 9906 | **+104** |

**没写 `.length` 的程序全都变小了**，因为那具死尸缩成了一条 `unreachable`。

三处记着绝对字节数的锁（`arrays_m3` / `closures_m3` / `function_values` 的
fleet 库大小）因此全部下移，每一处都就地写清了为什么——一个没有解释就变的常数，
正是那些测试存在的理由。

## §4 谓词：能精确到哪就精确到哪

门的谓词是：程序写了静态键 `length`，**或**写了任何一个文本无法判定的计算键。

计算键是个过近似，而且**必须**是：接收者是不是 String 是运行期事实，源码不说。
但文本能判定的两种情况被抠出来了：

* 数字字面量下标（`a[0]`）——永远不是字符串 `"length"`；
* 字符串字面量键（`o["a"]`）——是不是，源码直接写着。

这两条正是「索引任何东西的程序」的常见形状，抠出来之后它们分文不付。
剩下 `a[i]` 那 +95，是这个引擎没有类型推断的诚实代价，如实记在这里。

## §5 本里程碑刻意没有的东西

| 缺的 | 为什么 |
|---|---|
| 任何字符串**方法** | 需要接收者绑定：`"a".trim()` 的 `trim` 得拿到 `"a"`。今天没有 `this`，也没有把接收者绑进函数值的机制。这是下一个决定，不是本里程碑偷偷做掉的事。 |
| 数字 / 布尔的属性 | 同样需要一个包装机制；`(1).toFixed` 仍然 trap。 |
| `s.length = 0` | 写仍然 trap。ECMA-262 里它是 sloppy 模式的静默空操作，而静默空操作正是这个引擎拒绝的形状。 |
| 原型链本身 | 见 §1。这是一条臂，不是一个机制，文件头把话说死了。 |

**给下一个人的发现**：`Rt::Len` 之前是死代码这件事，是本次改动顺手量出来的。
无条件集合里可能还有别的死成员——值得单独扫一遍，那是一次纯收益的瘦身。
