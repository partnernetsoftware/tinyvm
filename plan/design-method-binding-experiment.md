## §0 背景，以及**已经定了、本实验不再讨论**的事

`"ab".length` 已经落地（`548fbbe`）。它是这条路上唯一**不需要绑接收者**的一格——
`length` 是个值不是个方法——所以它做完之后，`trim` / `map` / `join` / `toFixed`
全部卡在同一个问题上：

> `"a".trim()` 里的 `trim`，怎么拿到 `"a"`？

不在本实验讨论范围内的（已定）：

1. **V1 值表示不动**：`(tag: i32, payload: i64)`，八个 tag。
2. **门的名单不动**：`agenterm.*` 四个 import，不开第二扇 OS 面。
3. **无条件 runtime 集合的成员不动**：动它会移动后面所有函数索引。门做在**函数体**上，
   `design-string-length-milestone.md` §3 是先例。
4. **不引入 WasmGC**：核不吃。
5. **数组的 `undefined` vs 字符串的 trap 这条区别不动**：
   见 `design-string-length-milestone.md` §1，它是本引擎「不给错答案」的一个实例。

## §1 硬约束（违反则实验无效）

1. **纯 Rust，不链 C。** 任何方案都不许把 QuickJS 或别的 JS 引擎拉进来。
2. **不用这个特性的程序不多付字节。** 门必须存在且可度量；无方法调用的程序 Δ 必须为 0
   （或为负）。这条是布尔门，见 §3。
3. **不许给出「看起来像对的错答案」。** 具体到本题：读一个引擎没实现的方法
   （`"a".normalize`）必须 trap，不许返回 `undefined`——理由同 §0.5。
4. **拒绝必须具名**：够不到的东西给「this engine does not support X yet」，
   不给语法错误。
5. **不许悄悄加 `this`。** 方案 A 之外的方案里，一旦发现「要是有 `this` 就好办了」，
   那是**发现**，记进 §8，不是可以顺手加的东西——因为 `this` 一落地，
   `design-arrow-milestone.md` §1「箭头就是函数表达式」的等价立刻作废，
   那是**另一个**需要单独判决的结构性变化。

**病灶探测器**：任何为了让某个方法跑通而 **(a)** 往 V1 加第九个 tag、
**(b)** 给函数记录加第三个字段、或 **(c)** 在 `obj_get` 里再堆一条特判臂 的冲动，
是本实验要**检测**的病，不是要满足的需求。真需要就**记为发现**，不要偷偷加。

## §2 最小实验内容

三个变体，每个都实现**同一组四个方法**，不多不少：

| 方法 | 为什么选它 |
|---|---|
| `"s".trim()` | 字符串接收者，无参数，返回新字符串。最简的那一格。 |
| `"s".indexOf(x)` | 字符串接收者，**带参数**，返回数字。参数传递必须被测到。 |
| `a.push(x)` | 数组接收者，**改接收者本身**。绑定是不是「引用」在这里才看得出来。 |
| `a.map(f)` | 数组接收者，参数是**函数值**，要从 runtime 里回调进去。最贵的那一格，也是最能说明问题的那一格。 |

选四个而不是一个：**边际成本判据（§3 的 ③）需要至少两个点**，只做一个 = 零信息量。
选这四个而不是四个字符串方法：跨两种接收者才能看出机制是不是通用的。

三个变体：

**A · 加 `this`** —— 跟规范走。函数记录多一个接收者槽，调用约定多一个前置参数，
`o.m()` 把 `o` 填进去。

**B · 属性读返回绑好接收者的闭包** —— 复用刚落地的闭包机制（cell + 环境向量）。
`a.map` 读出来就是一个环境里装着 `a` 的函数值，可以存、可以传、可以稍后调。

**C · 调用点特化** —— `a.map(f)` 直接编成 `__arr_map(a, f)`，根本不产生函数值。
`let m = a.map; m(f)` 因此不成立——但那**今天本来就不成立**（读出来是 `undefined`），
所以 C 不是在拿掉现有能力。

## §3 判据

| # | 判据 | 性质 | 怎么量 |
|---|---|---|---|
| ① | 四个方法全部跑通且答案对 | **布尔门** | 每个方法至少三条断言，含一条边界（空字符串 / 空数组） |
| ② | 无方法调用的程序 Δ 字节 | **布尔门** | 必须 = 0 或 < 0，见 §1.2 |
| ③ | **加第五个方法的边际字节** | **斜率** | 实现四个之后再加 `"s".toUpperCase()`，量 Δ。**拆开记**：共享机制里增加多少 / 该方法自己多少 |
| ④ | **加第五个方法的边际改动行数** | **斜率** | 非空非注释行，不含测试与文档 |
| ⑤ | 用了方法的程序总字节 | 截距 | `let a=[1,2]; return a.map(x => x+1).length;` |
| ⑥ | 泄漏清单：为了让它跑通，V1 / 函数记录 / 调用约定 各被迫改了什么 | **清单** | 逐条列，这是主产出之一 |
| ⑦ | `let m = a.map; m(f)` 能不能用 | 清单 | C 明确不能；A/B 能。**不是**判负条件，只是如实记 |

**度量纪律**（照 `.claude/skills/decisive-experiment` §2.5）：

- 体积口径四元标签，三档全报：
  **L1** = 机制码（新增 runtime prefab，不含方法体）；
  **L2** = L1 + 四个方法的方法体；
  **L3** = 整个 `.wasm` 产物（`compile_qjs_m1(src).len()`，flat）。
  某档没测就写「未测定」，不许拿另一档的数填格。
- 工具：`compile_qjs_m1().len()`，**全轨统一**，不跨工具相除。
- 构建：本轨全部是 guest `.wasm`，不涉及 host 二进制，所以 `no_std` / `panic=abort`
  那条轴在这里**不适用**——明写出来，免得日后被人拿去和 host 侧的数并排。
- 基线：**取改动前那个提交**，不是 stash 后的工作树（`baseline-must-predate-your-change`）。
- 每个数字第三方可复跑，命令写进 `research/method-binding/RESULTS.md`。

## §4 判决树

```
0. kill criterion：任一变体 ① 不过 → 该变体出局，不看它别的数。
                   三个都不过 → 命题证伪（本引擎当前形状撑不起方法），立即停，写结论。
1. 主判据 = ③（边际字节）。若某变体的边际是**线性且陡**（每加一个方法都要动共享部分）
   → 判负，不看截距。今天小但线性增长的设计，输给今天略大但持平的设计。
2. ③ 打平 → 看 ④（边际行数）。同样看斜率不看截距。
3. ③④ 都打平 → 看 ⑥（泄漏清单）。**清单短的赢**，因为泄漏是不可逆的。
4. ⑥ 也打平 → 看 ⑤（截距）。
5. 若 A 在任何一步领先：**仍要单独回答 §1.5**——`this` 落地会作废箭头的等价，
   这笔账记在 A 头上，写进结论，不许略过。
```

**时间盒**：做到 ③ 出数为止。在此之前不做性能优化、不加第五个方法之外的任何方法、
不碰 `Math` / 全局对象。

## §5 目录——**开工前就改过一次，原因记在这里**

规格初稿把三个变体写成 `research/method-binding/variant-*/` 三个平行目录。
**那是错的**，而且是一开工就会撞上的错：这三个变体不是三个程序，是**同一个编译器的
三种改法**——它们都要动 `tinyvm-qjs` 的 `emit` / `runtime` / `repr`，
没法作为兄弟目录并存。按 `.claude/skills/decisive-experiment` §8「若发现规格本身有
bug，记下来并**修规格**」，改成：

```
crates/tinyvm-qjs/Cargo.toml     三个互斥 feature，**全部 default-off**
  method-this / method-bound / method-callsite

research/method-binding/
├── README.md        Q 编号索引：问题一句话 / 状态 / 结论 / 规格 / 实现
├── measure.rs       三档体积 + 边际成本，一个 test target，读 feature 决定量哪个
└── RESULTS.md       度量条件 → 逐判据数字 → 决策 trace → 偏差 → 复跑命令
```

这仍然是「**一份可分离的实现，打包三次**」——不要写三个独立原型：90% 工作重复，
而且会引入「哪个花的时间多」这个混淆变量。只是「打包」这里的意思是
`--features method-x`，不是三个目录。

**判决做完后三个 feature 全部删掉**，只留赢家（且赢家转成无 feature 的常规实现）。
feature 留在树上就是休眠模块，是 §4 表里第一条死法。

## §6 已排除的选项

| 选项 | 为什么排除 |
|---|---|
| 完整原型链（`[[Prototype]]` + `[[Get]]` 走链） | 它是**结果**不是**手段**：先得有绑定机制，链才有东西可查。而且它会顺手把 `Object.create` / `instanceof` / 属性遮蔽全拖进来，范围爆炸。 |
| WasmGC 的 `struct`/`array` | 核不吃，§0.4。 |
| 把方法实现成宿主 import | 违反 §0.2：门的名单是 `agenterm.*`，`String.prototype.trim` 不是宿主能力，是语言能力。 |
| 在 `obj_get` 里为每个方法名加一条臂 | 这正是病灶探测器 (c)。它的边际成本按方法数**线性**增长，③ 会直接判它负——但它便宜到有人会顺手写，所以明写在这里。 |

## §7 本实验不回答什么

- `Math` / `String` / `Number` / `Object` 这些**全局对象**怎么来（那是绑定问题，不是接收者问题）。
- `this` 该不该有（本实验只量它在方案 A 里的代价，不判它本身）。
- 方法**有多少个**、按什么顺序做。
- GC。方法会造更多临时对象，bump 堆的压力会变大——**这是本实验预期会产生的发现**，
  记进 §8，但不在这里解决。
- 性能（步数）。本轨只量体积与边际成本。
