## §0 真正的证据不在普查表里，在本产品自己身上

普查数的是下游 82 个 `.rh` 脚本，其中 38 个用 `import`。那是**代理指标**——
那些脚本不会明天就迁到 `.qjs`。真正的、非假设的证据是一句更短的话：

> **本仓库里唯一一个真实的 `.qjs` 产物是一个库，而它零消费者。**

`scripts/qjs/lib/fleet.qjs`：286 行，29 个 fleet 操作，与 `fleet.js` 一比一移植，
测试跑得通。用它的唯一办法是 `tests/qjs_produces_a_fleet_operation.rs` 里那一行：

```rust
fn with_binding(driver: &str) -> String {
    format!("{}\n{driver}", fleet_binding())   // 把整个库文本拼到脚本前面
}
```

**在 Rust 里做字符串拼接。** 磁盘上的一个 `.qjs` 文件没有任何办法用到它。
所以那个库不是「还没人用」，是**用不了**。

这条证据比普查表锋利，因为它不需要任何「将来会迁移」的假设。

## §1 这不是链接模型——上一轮的记录写错了，此处更正

`prd/PRD.md` 在 2026-08-28 记过一句：「`import` 不是语法特性而是**链接模型**，
多文件会改变『`.qjs → .wasm` 是编译一次』这句话还成不成立」。

**那句判断是错的，而且上面那段测试代码就是反证。** 那个 `format!` 说明所需的语义
本来就是**编译期把另一份源码取进来**——产物仍是一个 `.wasm`，仍是一次编译，
装载期仍只有一个模块，`Limits` 仍是一套。

要做的事因此是：**把测试里手工拼的那件事，由编译器做对**——「做对」的部分是
命名空间，而不是把两份源码的顶层名字倒进同一个作用域。

「编译一次到 `.wasm`」这句产品句**不受影响**。此条更正回填进 PRD。

## §2 硬约束

1. **编译器不碰文件系统。** `tinyvm-qjs` 是纯编译器，`no_std` 邻接。
   宿主提供 `Fn(&str) -> Option<String>` 解析回调，规格串怎么变成源码是**宿主的事**。
   这与「核只吃 wasm 字节」「不搬 tinyvm 源码」是同一条纪律。
2. **一个 `.wasm`。** 不产生第二个模块，不引入装载期链接。
3. **不 import 的程序付零字节。** 与模板 / 箭头 / 方法 / `for…of` 同一条门。
4. **语法照 ECMA-262。** 下游 42 处 `import` 全是 rh 的 `import "p" as n`，
   那告诉我们**需要命名空间导入**，不告诉我们该长什么样。`.qjs` 是 JavaScript，
   所以写 `import * as ns from "./lib.qjs"`，库侧写 `export`。
5. **病灶探测器**：任何「为了方便，让被导入模块的顶层名字直接落进导入者的作用域」
   的冲动，是本里程碑要**检测**的病。真需要就记为发现，不许偷偷做——
   那正是今天那个 `format!` 的行为，也正是要修掉的东西。

## §3 v1 的范围，以及为什么这样切

| 形式 | v1 | 理由 |
|------|----|------|
| `import * as ns from "SPEC"` | ✅ | 下游 42/42 都是这个形状 |
| `export function f() {}` | ✅ | 库要有办法说什么是公开的 |
| `export const x = …` | ✅ | 同上 |
| `import { a, b } from "SPEC"` | ❌ 具名拒绝 | ES 里更常见，但**当前需求为零**；等有 |
| `import d from "SPEC"`（默认） | ❌ 具名拒绝 | 同上 |
| `export default` | ❌ 具名拒绝 | 同上 |
| `export * from` / 再导出 | ❌ 具名拒绝 | 同上 |
| `import()` 动态 | ❌ 具名拒绝 | 需要装载期，违反约束 2 |
| 循环依赖 | ❌ **检测并点名** | 不是「以后做」，是必须现在就不静默 |

「当前需求为零就先不做」是本仓 2026-08-28 之后的既定做法：那天三次
「假设有需求、实测为零」（方法 / GC / `eval`）之后，路线图改成由语料驱动。
**`switch` 至今零使用，就一直排最后。**

## §4 判据（事前钉死）

| # | 判据 | 性质 | 通过线 |
|---|------|------|--------|
| ① | `fleet.qjs` 加上 `export` 后，一个 `.qjs` 脚本能 `import * as fleet` 并跑通真实 fleet 操作 | 布尔 | 那条端到端测试不再需要 `format!` 拼接 |
| ② | 不含 `import` 的程序，字节数不变 | 布尔 | **严格 0**，基线取改动前那个提交 |
| ③ | 命名空间不泄漏：被导入模块的顶层名字，在导入者作用域里**不可见** | 布尔 | 有测试断言引用它是「未声明」 |
| ④ | 循环导入被点名拒绝，不是栈溢出、不是挂死 | 布尔 | 诊断里出现两个规格串 |
| ⑤ | 每多导入一个模块的边际字节 | 斜率 | 记录；同一个模块被导入两次只应算一次 |
| ⑥ | 上游套件 + 下游两条验证命令 | 布尔 | 失败集合逐条不变 |

判据 ③ 是 §2 那条病灶探测器的可判定形式。判据 ⑤ 里「两次只算一次」不是优化，
是**语义**：ECMA-262 的模块图里一个模块只求值一次。

## §5 判决树与时间盒

```
1. 先做解析回调 + `import * as` + `export`，只在**上游测试**里验。
   判据 ② 不为 0 → 停，先解决门控。
2. 再做循环检测（判据 ④）。这条不许推迟到 v2：静默挂死比缺特性坏得多。
3. 最后动下游：给 fleet.qjs 加 export，把那条端到端测试的 format! 拼接换掉（判据 ①）。
kill criterion: 若为了让命名空间成立，必须给运行时加一个新的对象种类
   （即 §2 病灶探测器响了），停下来记为发现——命名空间应当是**已有的对象**，
   函数是值这件事 rev f21f0f2 就有了。
时间盒: 做到判据 ① 出结果为止。在此之前不做具名导入、不做默认导出、不做优化。
```

## §6 本里程碑不回答什么

- **规格串怎么解析成文件**：那是宿主的策略（相对路径？项目根？扩展名补全？），
  编译器只拿到一个字符串。下游要单独定，且要能说明 `../` 逃逸怎么处理。
- **`for … in`**、具名导入、默认导出：都在 §3 表里，具名拒绝。
- **模块级 `this`、顶层 `await`**：不在子集里，本里程碑不改变这一点。
